# Short-ID cursor pagination for note listing

`flicknote list` and MCP `note_list` will accept the same pagination inputs: a bounded `limit` and an optional `cursor`, which is the final short ID from the preceding page. Listing is ordered by `short_id DESC`, and a continuation selects `short_id < cursor`, so new higher IDs do not shift or duplicate later pages. No `next_cursor` is returned: callers derive the next cursor from the final returned item's public `id` and stop on an empty page. A successfully created note must already have a short ID before it is committed locally, making that public ID the complete stable ordering key. This slice deliberately excludes `find` / `note_find`, whose updated-time search ordering needs its own product decision.
